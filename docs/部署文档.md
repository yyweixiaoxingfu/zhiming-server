# 知命罗盘 · 后端部署文档

本文档面向拿到源码后从零部署的开发者，覆盖 **Windows（phpEnv / phpStudy）** 与
**Linux（宝塔面板 / 命令行 Nginx、Apache）** 四种环境。

- 第 0～2 节是**所有环境通用的**，请先看完；
- 第 3 节按你使用的面板/系统挑一条照做即可；
- 遇到问题先查 [第 9 节 常见问题排查](#9-常见问题排查)。

---

## 0. 最重要的一件事：PHP 版本必须是 7.4.x

**本项目只能运行在 PHP 7.4.x，不能是 PHP 8.0 及以上，也不建议低于 7.4。**

原因（已实测）：

| PHP 版本 | 结果 |
| --- | --- |
| 8.0 / 8.1 / 8.2 | **致命错误，整个站点打不开**。实测 PHP 8.2 报错：`Return type of think\Container::offsetExists($key) should either be compatible with ArrayAccess::offsetExists(mixed $offset): bool`（`thinkphp/library/think/Container.php:579`）。这是 ThinkPHP 5.1 框架本身的限制，无法通过改配置绕开。 |
| **7.4.x** | ✅ **推荐，唯一同时满足框架与全部依赖的版本** |
| 7.2 / 7.3 | 框架可运行，但 `phpoffice/phpspreadsheet 1.30` 要求 `^7.4 \|\| ^8.0`，`composer install` 会失败 |
| 5.6 ~ 7.1 | 依赖版本约束不满足，无法安装 |

> phpEnv / phpStudy / 宝塔都支持**多 PHP 版本共存**，服务器上同时装 PHP 8 和 PHP 7.4
> 并不冲突，只要**给这个站点单独指定 PHP 7.4** 即可。这是最容易出错的一步。

确认版本：

```bash
php -v        # 应输出 PHP 7.4.x
```

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| PHP | **7.4.x**（见上一节） |
| MySQL | 5.7+ 或 MariaDB 10.2+，字符集 `utf8mb4` |
| Composer | 2.x |
| Web 服务器 | Nginx / Apache / IIS |
| 操作系统 | Windows（本地开发 / 内网）或 Linux（生产推荐） |

**必需 PHP 扩展**（缺任意一个都会报错）：

`pdo_mysql`、`mbstring`、`openssl`、`gd`、`json`、`curl`、`fileinfo`、`zip`、
`simplexml`、`dom`、`bcmath`

**可选扩展**：`redis`（改用 Redis 缓存）、`pcntl` + `posix`（仅 Linux，IM 服务需要）、`sockets`（Workerman）

检查扩展：

```bash
php -m
```

> 宝塔用户请在「软件商店 → PHP-7.4 → 安装扩展」里确认已装 **fileinfo**（导出 Excel 需要）
> 和 **gd**（后台验证码需要）——这两个在部分面板默认不装。

## 2. 通用部署流程（所有平台都要做）

> 下面 Windows 用 `项目目录` 指代如 `D:\www\zhiming-server`，
> Linux 用 `/www/wwwroot/zhiming-server`。

### 第 1 步：放置代码

把完整仓库放到目标目录，**不要只放 `public/`**。该目录下应能看到
`application/`、`thinkphp/`、`public/`、`composer.json`。

> ⚠️ **路径不要包含中文和空格**，否则 Composer 与部分 PHP 函数会异常。

### 第 2 步：安装 Composer 依赖

```bash
cd 项目目录
composer install --no-dev -o
```

> 仓库的 `.gitignore` 已排除 `vendor/`，所以这一步**不能跳过**。
> 若目标机器没有 Composer：在本机执行后把 `vendor/` 整个目录一起拷过去也可以。

### 第 3 步：创建环境配置

```bash
cp .env.example .env        # Windows 若没有 cp，直接复制文件改名即可
```

编辑 `.env`（`.env` 在**项目根目录**，与 `composer.json` 同级）：

```ini
APP_DEBUG = false          ; 公网部署务必为 false

[DATABASE]
HOSTNAME = 127.0.0.1
DATABASE = zhiming         ; 第 4 步创建的库名
USERNAME = 你的数据库账号
PASSWORD = 你的数据库密码
HOSTPORT = 3306
PREFIX = w_                ; 不要改，SQL 文件用的是 w_ 前缀

[JWT]
SECRET = 换成一串随机字符串   ; 必改！
JWT_TTL = 40000
JWT_REFRESH_TTL = 120
```

生成随机 JWT 密钥：

```bash
php -r "echo bin2hex(random_bytes(32)); echo PHP_EOL;"
```

### 第 4 步：创建数据库并导入

建库（字符集必须 `utf8mb4`）：

```sql
CREATE DATABASE zhiming DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

导入初始化 SQL（文件名以你实际拿到的为准，仓库根目录下的 `databsae.sql` 为示例）：

```bash
mysql -u root -p zhiming < databsae.sql        # Linux / Windows 命令行
```

Windows 面板用户更简单：用 phpEnv / phpStudy / 宝塔自带的 **phpMyAdmin**，
选中 `zhiming` 库 → 导入 → 选择 SQL 文件 → 执行。

> ⚠️ 若 SQL 文件较大（十几 MB），phpMyAdmin 默认上传上限可能不够，
> 需先调大 `upload_max_filesize` 与 `post_max_size`，或改用命令行导入。

> ⚠️ 如果你拿到的是未清洗的 SQL，导入后请**立刻修改后台管理员密码**，
> 该文件可能残留原环境的管理员账号、会员手机号与第三方密钥。

### 第 5 步：生成安装锁文件（关键，最容易漏）

**Linux / macOS：**

```bash
mkdir -p data && touch data/install.lock
```

**Windows（CMD，没有 touch 命令）：**

```cmd
mkdir data
type nul > data\install.lock
```

**Windows（PowerShell）：**

```powershell
New-Item -ItemType Directory -Force -Path data
New-Item -ItemType File -Force -Path data\install.lock
```

> **为什么必须做**：`public/index.php` 和 `public/admin.php` 都会检查
> `data/install.lock`。文件不存在时，程序会尝试跳转到安装引导模块，而
> 本项目**并未包含安装模块**，此时会直接报「模块不存在」错误。
> 因此数据库导入完成后，必须手动创建这个空文件。

### 第 6 步：设置目录权限

**Linux：**

```bash
cd /www/wwwroot/zhiming-server
chmod -R 755 runtime log data public/uploads
chown -R www:www .        # 宝塔/Nginx 常为 www；Apache 常为 www-data / apache
```

**Windows**：NTFS 默认可写，一般无需设置。若用 IIS 报权限不足，
给 `IIS_IUSRS` 用户组对 `runtime`、`log`、`data`、`public\uploads` 授予「修改」权限即可。

确认 `public/uploads` 子目录存在（缺目录会导致上传失败）：

```bash
ls public/uploads     # 应有 files flashs images temp videos voices 等目录
```

### 第 7 步：配置 Web 服务器

**站点根目录必须指向 `public/`**，不是项目根目录。

具体做法按平台见 [第 3 节](#3-分平台部署指南)。

### 第 8 步：验证

浏览器或命令行访问：

```bash
curl -X POST http://你的域名/index.php/index/index/system_config
```

返回 JSON（含 `code` 字段）即说明后端已跑通。
更直观的做法是直接打开后台登录页，能显示登录框即部署成功：

```
http://你的域名/admin.php/user/publics/signin.html
```

（初始账号 `admin` / `123456`，详见 [第 4 节](#4-初始化后台)。）

## 3. 分平台部署指南

### 3.1 Windows · phpEnv

> phpEnv（官网 <https://www.phpenv.cn>）是 Windows 上的绿色 PHP 集成环境，
> 自带 Apache / Nginx、支持多 PHP 版本共存、**内置 Composer**，适合本地开发。
> 不同版本菜单位置略有差异，以下按功能描述，找不到就找同名功能。

1. **安装并启动**：下载 phpEnv，安装后启动 **Nginx（或 Apache）+ MySQL**。
2. **安装 PHP 7.4**：在软件/环境管理中**添加 PHP 7.4** 并设为该站点使用的版本
   （phpEnv 支持多版本共存与自定义版本）。
3. **添加站点**：
   - 域名：`zhiming.test`（或直接用 `localhost` + 端口）
   - **网站根目录**：`D:\www\zhiming-server\public`（注意是 `public`）
   - PHP 版本：**7.4**
4. **配置伪静态**：站点 → 网站配置 → **伪静态配置**，粘贴：

   若用 Nginx：

   ```nginx
   location / {
       if (!-e $request_filename) {
           rewrite ^(.*)$ /index.php?s=$1 last;
           break;
       }
   }
   ```

   若用 Apache：项目已自带 `public/.htaccess`，确认开启 `mod_rewrite` 即可，无需另配。

5. **创建数据库**：用 phpEnv 自带的数据库管理工具（或 phpMyAdmin）建库
   `zhiming`，字符集 `utf8mb4`，再导入 SQL。
6. **安装依赖**：打开 phpEnv 内置终端，`cd` 到项目根目录执行 `composer install --no-dev -o`。
7. **生成安装锁**：按第 5 步的 Windows 命令创建 `data\install.lock`。
8. 访问后台登录页 `http://zhiming.test/admin.php/user/publics/signin.html`，
   用 `admin` / `123456` 登录。

### 3.2 Windows · phpStudy（小皮面板）

> phpStudy Pro / 小皮面板（官网 <https://www.xp.cn>），支持 Windows 与 Linux。

1. **安装并启动**：安装后启动 **Nginx（或 Apache）+ MySQL**。
2. **安装 PHP 7.4**：打开「软件管理」，找到 **PHP 7.4** 安装
   （若列表中没有，可在软件管理里查找其它版本源）。安装后回到首页启动它。
3. **创建网站**：网站 → 创建网站
   - 域名：`zhiming.test`
   - **根目录**：`D:\phpstudy_pro\WWW\zhiming-server\public`
   - **PHP 版本**：选择 **7.4**（每个站点可单独指定版本）
   - 可勾选「同步创建数据库」，字符集选 `utf8mb4`
4. **配置伪静态**：网站 → 对应站点 → **伪静态**，粘贴 3.1 中的 Nginx 规则。
   Apache 环境直接用自带的 `public/.htaccess`。
5. **安装依赖**：phpStudy 部分版本自带 Composer，否则到
   <https://getcomposer.org> 下载 `Composer-Setup.exe` 安装。
   之后在项目根目录执行 `composer install --no-dev -o`。
6. **导入数据库**：phpStudy → 数据库 → phpMyAdmin，导入 SQL。
7. **生成安装锁**：按第 5 步创建 `data\install.lock`。
8. 访问后台登录页 `http://zhiming.test/admin.php/user/publics/signin.html`，
   用 `admin` / `123456` 登录。

> ⚠️ phpStudy 默认可能开启**防跨站（open_basedir）**。若页面报
> `open_basedir restriction in effect`，请到该站点的设置里**关闭防跨站攻击**。

### 3.3 Linux · 宝塔面板（生产推荐）

1. **安装宝塔**：按 <https://www.bt.cn> 指引安装（推荐 LNMP）。
2. **安装运行环境**：软件商店依次安装 **Nginx**、**MySQL 5.7+**、**PHP-7.4**。
   装完 PHP-7.4 后进入其「安装扩展」，确认 **fileinfo**、**gd**、**bcmath** 已装。
3. **添加站点**：网站 → 添加站点
   - 域名：`api.example.com`
   - **根目录**：`/www/wwwroot/zhiming-server`（先填项目根，稍后改运行目录；
     也可以直接填 `/www/wwwroot/zhiming-server/public`，二选一即可）
   - 数据库：选 MySQL，字符集 `utf8mb4`，记下账号密码
   - **PHP 版本：PHP-74**（这一步最关键）
4. **调整站点配置**：
   - **网站目录 → 运行目录**：设为 `/public`（若第 3 步根目录已指向 public 则跳过）
   - **关闭「防跨站攻击(open_basedir)」** —— 不关会报 `open_basedir restriction in effect`
   - **伪静态**：粘贴以下规则（宝塔虽有 thinkphp 预设，但建议用这段）：

     ```nginx
     location / {
         if (!-e $request_filename) {
             rewrite ^(.*)$ /index.php?s=$1 last;
             break;
         }
     }
     ```

5. **上传代码并装依赖**：SSH 登录服务器

   ```bash
   cd /www/wwwroot/zhiming-server
   composer install --no-dev -o
   cp .env.example .env
   vim .env          # 填写数据库账号密码与 JWT 密钥
   ```

6. **导入数据库**：宝塔 → 数据库 → 对应库 → **导入** / phpMyAdmin 导入 SQL。
7. **设置权限与安装锁**：

   ```bash
   cd /www/wwwroot/zhiming-server
   chown -R www:www .
   chmod -R 755 runtime log data public/uploads
   touch data/install.lock
   ```

8. 访问后台登录页 `http://api.example.com/admin.php/user/publics/signin.html`，
   用 `admin` / `123456` 登录；配置 SSL 后改用 HTTPS。

> 宝塔提示：站点创建后会自动生成 `.user.ini` 限制跨目录访问，
> 若出现 500 或 `open_basedir` 报错，**删除该文件**并在面板关闭防跨站即可。

### 3.4 Linux · 命令行 Nginx

```nginx
server {
    listen 80;
    server_name api.example.com;
    root /www/wwwroot/zhiming-server/public;
    index index.php index.html;

    location / {
        if (!-e $request_filename) {
            rewrite ^(.*)$ /index.php?s=$1 last;
            break;
        }
    }

    location ~ \.php$ {
        fastcgi_pass   127.0.0.1:9000;      # 按实际 PHP-FPM 地址修改
        fastcgi_index  index.php;
        fastcgi_param  SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include        fastcgi_params;
    }

    # 禁止访问敏感目录
    location ~ ^/(runtime|data|application|thinkphp|vendor)/ {
        deny all;
    }

    client_max_body_size 20m;
}
```

### 3.5 Linux · 命令行 Apache

项目已自带 `public/.htaccess`，开启 `mod_rewrite` 与 `AllowOverride All` 即可。

```apache
<VirtualHost *:80>
    ServerName api.example.com
    DocumentRoot /www/wwwroot/zhiming-server/public
    <Directory /www/wwwroot/zhiming-server/public>
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
```

## 4. 初始化后台

### 后台登录地址与初始账号

浏览器打开后台登录页：

```
http://你的域名/admin.php/user/publics/signin.html
```

| 项 | 值 |
| --- | --- |
| **登录地址** | `http://你的域名/admin.php/user/publics/signin.html`<br>（把 `你的域名` 换成实际域名或 `localhost:端口`） |
| **用户名** | `admin` |
| **密码** | `123456` |

本地示例：

```
http://localhost/admin.php/user/publics/signin.html
http://zhiming.test/admin.php/user/publics/signin.html
http://api.example.com/admin.php/user/publics/signin.html
```

> ⚠️ **不要只访问 `http://你的域名/admin.php`** —— 本项目后台默认模块下没有
> 对应的 `index` 入口，直接访问会报错。请务必使用上面完整的登录地址。

> 🔐 **登录后第一件事就是修改密码**（右上角个人设置 → 修改密码）。
> 这个弱口令对公网部署是明确的安全风险。

> 后台登录验证码默认关闭（`admin_config` 表中 `captcha_signin` 为 `0`）。
> 如需开启，可在后台「系统 → 系统设置 → 系统 → 后台验证码开关」中打开，
> 但需要 PHP 已安装 `gd` 扩展。

### 登录后必做配置

| 位置 | 配置项 | 说明 |
| --- | --- | --- |
| 系统 → 系统设置 → 基本 | 站点标题、域名、版权、备案号 | |
| 系统 → 系统设置 → 上传 | 上传驱动、大小限制、水印 | |
| 系统 → 支付配置 | 支付宝 / 微信 `appid`、商户号、密钥、证书 | 商业化才需要 |
| 系统 → 平台配置 | 短信通道账号、AI 模型密钥、ASR / TTS 地址 | 对应 `config/wechat.php`、`config/payment.php` 中的空占位 |
| 会员 / 财务 | 提现规则、分销比例 | |

同时建议在代码层面修改 **用户加密密钥**：

```php
// config/app.php
'data_auth_key' => '填写一串随机字符串',   // 默认为空，务必修改
```

关闭调试（公网必须）：

```php
// config/app.php
'app_debug' => false,
// config/database.php
'debug' => false,
```

并把 `.env` 中的 `APP_DEBUG` 设为 `false`。

## 5. 跨域说明

`public/index.php` 已内置 CORS 响应头：

```php
header('Access-Control-Allow-Origin: *');
header('Access-Control-Allow-Credentials: true');
header('Access-Control-Allow-Headers: Content-Type, ..., Origin,Authorization');
```

前端使用 `Authorization` 请求头传 JWT，不依赖 Cookie，因此默认配置可直接工作。
若后续需要携带 Cookie，请把 `Access-Control-Allow-Origin` 改成**具体的前端域名**
（`*` 与 `Allow-Credentials: true` 组合在浏览器中会被拒绝）。

## 7. 可选：启动 IM 服务

即时通讯基于 GatewayWorker，不使用 IM 功能可跳过。

```bash
php public/start_im.php start        # 前台运行
php public/start_im.php start -d      # 守护进程运行
```

默认端口：`8282`（WebSocket）、`1236`（Register）、`8283`（Business）。
可修改 `config/gateway.php` 或通过环境变量覆盖。

> ⚠️ **Windows 下无法运行 IM 服务**：GatewayWorker 依赖 `pcntl` 与 `posix` 扩展，
> Windows 版 PHP 不提供。请在 Linux 上部署，并在防火墙放行 `8282` 端口。

## 9. 常见问题排查

### 通用

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| 打开首页报 `Return type of think\Container::offsetExists...` | PHP 版本 ≥ 8.0 | **给该站点切换到 PHP 7.4**（见第 0 节） |
| 提示「模块不存在:install」或访问 `index.php` 空白 | 缺少 `data/install.lock` | 按第 5 步创建该文件 |
| 访问 `admin.php` 报错 / 空白，不知道后台在哪 | 后台不是根路径 | 用完整地址：`http://你的域名/admin.php/user/publics/signin.html` |
| 登录页打不开，提示控制器不存在 | URL 少了 `.html` 后缀 | 项目 `url_html_suffix` 为 `html`，请以 `.html` 结尾 |
| 500 错误、页面空白 | `runtime/` 不可写，或调试已关闭看不到报错 | 检查 `runtime` 权限；临时把 `APP_DEBUG` 改回 `true` 看具体报错 |
| `composer install` 报依赖冲突 | PHP 版本不对 | 用 PHP 7.4 执行 `composer install` |
| 数据库连接失败 | `.env` 配置错误，或 `.env` 位置不对 | 确认 `.env` 在**项目根目录**（与 `composer.json` 同级） |
| 后台验证码图片不显示 | 缺 `gd` 扩展 | 安装 `php-gd` 后重启 Web 服务 |
| 上传图片失败 | `public/uploads` 不可写或子目录缺失 | 检查权限与子目录，见第 6 步 |
| 前端请求返回 401 | JWT 密钥不一致，或 token 过期 | 确认前后端使用同一 `JWT.SECRET`；重新登录 |
| 前端提示跨域被拦截 | 服务端 CORS 被 Nginx 覆盖 | 不要在 Nginx 再写一遍 `add_header Access-Control-Allow-Origin`，让 PHP 输出即可 |
| 导出 Excel 报错 | 缺 `zip` 或 `fileinfo` 扩展 | 安装后重启 PHP-FPM |
| 接口很慢 | 缓存未生效 | 确认 `runtime/` 可写；生产环境建议改 Redis（见 `config/cache.php` 注释段） |

### Windows（phpEnv / phpStudy）

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| `'composer' 不是内部或外部命令` | Composer 未安装或未加入 PATH | 用面板内置 Composer；或安装 `Composer-Setup.exe` 后重开终端 |
| `'php' 不是内部或外部命令` | PHP 未加入系统 PATH | 用面板自带终端；或把 PHP 7.4 目录加入 PATH |
| `'touch' 不是内部或外部命令` | Windows 没有该命令 | 改用 `type nul > data\install.lock` |
| 只有首页能打开，其它页面 404 | 伪静态未生效 | 在站点「伪静态」里粘贴第 3.1 节的规则并保存 |
| `No input file specified` | 根目录指向错误，或 Nginx 未传 `SCRIPT_FILENAME` | 确认站点根目录指向 `public` |
| `open_basedir restriction in effect` | 面板开启了防跨站 | 站点设置里关闭「防跨站攻击」，或删除 `.user.ini` |
| 页面显示乱码 / 中文注释乱码 | 编辑器编码问题 | 用 UTF-8 打开；不影响运行 |
| IM 服务起不来 | Windows 缺 `pcntl`/`posix` | Windows 无法运行 IM，请在 Linux 部署（见第 7 节） |

### Linux（宝塔）

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| 500 + `open_basedir restriction in effect` | 宝塔防跨站拦截 | 站点 → 网站目录 → 关闭防跨站攻击；删除 `.user.ini` |
| 访问 `/admin.php` 404 | 运行目录没指向 public | 站点 → 网站目录 → 运行目录设为 `/public` |
| `fileinfo` / `gd` 相关报错 | PHP 扩展未装 | 软件商店 → PHP-7.4 → 安装扩展 → 装 `fileinfo`、`gd` |
| `composer install` 用错 PHP 版本 | 服务器默认 PHP 是 8.x | 用宝塔的 PHP-7.4 执行：`/www/server/php/74/bin/php /usr/bin/composer install` |
| 上传文件超过限制 | Nginx / PHP 上传上限 | 调大 `client_max_body_size`、`upload_max_filesize`、`post_max_size` |
| 导入大 SQL 超时 | phpMyAdmin 限制 | 改用命令行 `mysql -u root -p zhiming < databsae.sql` |

## 10. 备份与升级

**备份**：定期备份数据库（`mysqldump`，宝塔可在「数据库 → 备份」设置定时任务）
+ `public/uploads/` 目录。后台「系统 → 数据库备份」也提供导出功能。

**升级**：拉取新代码后执行

```bash
composer install --no-dev -o
rm -rf runtime/cache/* runtime/temp/*     # Windows 直接删除 runtime\cache 下文件
```

然后对比 `application/` 下各模块的 `install.sql` / 变更说明，按需执行增量 SQL。
